## Part 1 — Minibits Wallet

### 1.1 Description

Minibits Wallet is an open-source mobile application for Android and iOS that implements ecash wallets backed by Bitcoin via the Cashu protocol and the Lightning Network. The associated public LNURL server provides Lightning address and NOSTR-based identity services under the minibits.cash domain (e.g. yourname@minibits.cash).

The Wallet is in beta. It is provided as a tool to explore how Bitcoin-backed ecash can enable instant, low-cost, and private value transfer.

### 1.3 Ecash and Mint Trust Model

The Wallet is software only. All ecash is issued by the mint you choose to use, and every claim embodied in ecash exists solely against the mint that issued it. - To redeem or receive your ecash you trust the mint that has issued it.
- The mint does not coordinate ecash transfers - those happen directly between wallets using QR codes, NFC or internet. Mint solely provides minting, swapping and melting (redeeming) services based on wallet request.

### 2.4 Mint Keyset Rotation

The Mint issues ecash using cryptographic keysets. In accordance with the Cashu protocol, the Mint may rotate its active keyset — that is, retire an existing keyset and introduce a new one — for operational or security reasons. Keyset rotations are expected to occur periodically, typically no more than once per calendar year under normal operating conditions, but may occur at any time and without prior notice if a security concern requires it.

Upon a keyset rotation:

- Ecash issued under the previous ("retired") keyset remains valid for redemption and swap for a transitional period of twelve (12) months from the date of rotation.
- During that transitional period, the Mint will continue to honour swap requests that exchange retired-keyset ecash for freshly issued ecash under the current active keyset. Wallets that support keyset rotation — including the Minibits Wallet — will perform this swap automatically while the user actively uses the wallet.
- If you use a wallet only occasionally or one that does not handle keyset rotation automatically, you are responsible for manually swapping any retired-keyset ecash before the transitional period expires.
- After the twelve-month transitional period, the retired keyset may be removed from the Mint's database at any time and without further notice. Ecash that has not been swapped before removal will no longer be honoured by the Mint. The Operator bears no liability for ecash lost because it was not swapped within the transitional period.

The Operator will endeavour to announce scheduled keyset rotations in advance through the project's website and social network profiles. The current active keyset and any retired keysets still within their transitional period are always queryable via the Mint's keys endpoint.

## Part 3 — Minibits Ippon

### 3.1 Description

Minibits Ippon ("Ippon") is an experimental, open-source ecash and Lightning wallet implementation developed within the Minibits project. It is designed primarily for non-human systems — in particular AI agents and automated processes — that require programmatic access to micropayment capabilities. Ippon is available as:

- A wallet server providing a REST API;
- An MCP (Model Context Protocol) server facade, provided by the companion minibits_ippon_mcp project, which wraps the Ippon API for AI agent integration;
- A local CLI tool for agent-controlled deployments.

Ippon is released as open-source software under the MIT Licence.

### 3.2 Alpha Software Disclaimer

> **ALPHA SOFTWARE — CRITICAL RISK NOTICE**
>
> Ippon is alpha-stage software. It may contain serious bugs, security vulnerabilities, and incomplete features. **Production use of Ippon requires a self-hosted instance deployed under your own control.** Use the Hosted Ippon exclusively for evaluation, development and testing, with small amounts only. **Do not hold funds you cannot afford to lose.** The Hosted Ippon may be reset, reconfigured, or discontinued at any time.

### 3.3 Intended Users

Ippon is intended for:

- Developers and researchers evaluating ecash payment capabilities for AI agent or automated workflows.
- Cashu mint operators exploring complementary wallet tooling.
- AI agents or automated systems acting on behalf of and under the control of a responsible developer or operator.

Ippon operating models are:

- Hosted deployment accessed by AI agents or by any automated process over the network through the REST API;
- Hosted deployment accessed by AI agents using the dedicated MCP server;
- Local installation by the AI agent that is accessed privately using local CLI commands.

Ippon is not intended for general consumer use. By using the Hosted Ippon or deploying your own instance, you represent that you fall within one of the above categories and that you understand the alpha-stage nature of the software.

### 3.4 Security

Ippon is an ecash wallet that holds ecash in its own database. Wallet access is controlled by a bearer access_key issued at wallet creation time. You are responsible for:

- Securing the access_key associated with each wallet. Any party who obtains the access_key can access and drain the wallet.
- Securing the database if you use a self-hosted Ippon instance. Any party who obtains access to that database can drain the wallet.
- Emptying your wallets at the conclusion of each agentic session or project. Ippon wallets are designed to be short-lived and must not hold balances over the long term.

The MCP server component (minibits_ippon_mcp) manages access_keys on behalf of agents and links them to session identifiers to reduce the risk of key exposure. However, the operator of the MCP server instance remains responsible for securing the underlying infrastructure.

### 3.5 Hosted Minibits Ippon Instance

The Hosted Ippon at ippon.minibits.cash, including its MCP server, is a capped developer preview operated by the Operator free of charge, solely for evaluation, development and interoperability testing. It must not be used in production, for commercial purposes, or to hold balances beyond the published limits, which are deliberately set at nominal amounts. Wallets on the Hosted Ippon are short-lived by design and should be emptied at the end of each session or project.

The Hosted Ippon enforces strict limits on wallet balances, payment amounts and wallet creation rates, and is subject to Section 0.8. Current limits are published via the `GET /v1/info` endpoint. The Operator may change these limits at any time without notice. The Operator makes no commitment regarding uptime, availability, or continuity of the Hosted Ippon, which may be reset or discontinued at any time; where practicable, notice will be given so that balances can be withdrawn.
